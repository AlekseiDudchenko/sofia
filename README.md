# Таблица умножения

Тренажёр таблицы умножения 2–9 для ребёнка. Статическая страница: без сервера,
без базы, без аккаунта. Ставится на домашний экран и работает офлайн, весь
прогресс лежит в `localStorage` устройства и никуда не отправляется.

## Как это устроено

**36 карточек вместо 64.** `7×8` и `8×7` — одна карточка: коммутативность
дублировать незачем, а порядок множителей в вопросе всё равно случайный.

**Оценка по скорости, а не по самооценке.** Ребёнок не жмёт «легко/трудно» —
приложение само смотрит на время до первой нажатой цифры. Для таблицы
умножения правильный ответ через восемь секунд означает, что она досчитала,
а не вспомнила, и засчитывать его как успех нельзя.

| Ответ | Что происходит со ступенью |
|---|---|
| быстрее 2 с | вверх |
| 2–6 с | на месте |
| дольше 6 с | вниз |
| дольше 15 с | не трогаем — скорее отвлеклась |
| ошибка | сброс в начало, переспрос через 4 примера |

**Ступень растёт только от быстрого ответа**, поэтому «на автомате»
(ступень 5) по построению значит пять быстрых ответов в разные дни.
Интервалы по ступеням: 1, 1, 2, 4, 8, 16, 32 дня.

**Ступень двигается не чаще раза в день.** Иначе переспрос после ошибки в той
же сессии воскрешал бы карточку, которую пять минут назад не знали.

**Новые факты вводятся по 6 в день** и не по порядку номеров, а от простого к
сложному: ×2 → ×5 → ×9 → ×3 → ×4 → 6·7·8. Девятка идёт рано намеренно — у неё
есть приём «на десятку минус число».

**Спринт не двигает расписание.** Минута на скорость — это награда и разминка;
если бы её ответы влияли на интервалы, десяток быстрых ответов подряд объявил
бы факт выученным. Спринт даёт очки, рекорд и дневную норму, не более.

**Миньоны рисуются кодом, а не лежат картинками.** Довод тот же, что и со
звуком: файл пришлось бы тянуть по сети и класть в офлайн-кэш, а растровый —
ещё и в трёх размерах. Один SVG-контур тянется от значка в ряду команды до
итогов подхода и красится теми же переменными, что и остальной интерфейс.

Настроение при этом не украшение. На главной миньон спит, пока за день не
ответили ни разу, и ликует, когда норма закрыта, — это и есть индикатор нормы.
На тренировке он прыгает от быстрого ответа, просто улыбается обычному и
жмурится от ошибки: реакция доходит раньше, чем ребёнок дочитает подсказку.
Прыжок достаётся только быстрому ответу, потому что разница между «вспомнила»
и «досчитала» — единственное, что здесь стоит подчёркивать.

**Команда приходит по одному за шесть выученных карточек.** Шесть миньонов на
36 фактов. Карта таблицы показывает, сколько ещё осталось, и от неё всегда
немного грустно; команда показывает то же самое с другой стороны — сколько уже
сделано — и растёт заметными скачками, а не по клетке за раз.

**Звук синтезируется, а не проигрывается из файлов.** Щелчки клавиш, отклик на
ответ, отсчёт последних секунд спринта и фанфара рекорда собраны из
осцилляторов Web Audio. Файлы пришлось бы держать в репозитории, тянуть по
сети и класть в офлайн-кэш — ради сигналов длиной в десятую долю секунды это
несоразмерно. Ошибка звучит тише и ниже правильного ответа, а не резче:
неверный ответ здесь обычная часть тренировки, пугать за него нечем.
Выключается кнопкой в панели тренировки и в настройках на главной; выбор
хранится отдельно от прогресса — в копию не попадает и «Начать заново» его не
трогает.

## Разработка

```
npm ci
npm run build     # tsc: src/ -> web/js/, затем штамп версии в sw.js
npm test          # юнит-тесты чистой логики
npm start         # http://localhost:5173
npm run test:e2e  # браузерные тесты (нужен npx playwright install chromium)
```

Юнит-тесты импортируют **скомпилированные** модули из `web/js/`, поэтому
`npm run build` перед `npm test` обязателен — иначе тесты не найдут файлы.

Иконки генерируются из кода без внешних зависимостей: `node scripts/make-icons.mjs`.
Ту же фигуру — миньона со знаком умножения вместо зрачка — повторяет вручную
`web/icons/icon.svg`: у растра и вектора общего источника нет, и правку нужно
вносить в оба файла.

### Что где лежит

| Путь | Что это |
|---|---|
| `src/facts.ts` | колода из 36 фактов и порядок их ввода |
| `src/rating.ts` | время ответа → оценка |
| `src/scheduler.ts` | лестница интервалов |
| `src/session.ts` | сборка очередей тренировки и спринта |
| `src/answer.ts` | посимвольная проверка ввода |
| `src/store.ts` | `localStorage`, дневная статистика, копии |
| `src/sound.ts` | синтез сигналов на Web Audio |
| `src/ui/minion.ts` | контур миньона и его настроения |
| `src/ui/` | экраны |
| `web/` | то, что публикуется; `web/js/` собирается из `src/` |

`web/sw.js` — рукописный исходник, но две константы в нём проставляет
`npm run build`: версию кэша из `package.json` и список скомпилированных
модулей из `web/js/`. Поэтому новый файл в `src/` требует пересборки и коммита
`web/sw.js` — в CI стоит `git diff --exit-code`, и забытая пересборка уронит
сборку, а не уедет в прод молча. `web/js/` в git не хранится.

## Публикация

GitHub Pages разворачивается из `web/` при пуше в `main`
(`.github/workflows/deploy.yml`). Один раз нужно включить в настройках
репозитория **Settings → Pages → Source: GitHub Actions**.

Маршрутизация по хэшу (`#/drill`), поэтому приложение работает из любого
подкаталога и не требует SPA-фолбэка.

**Каждый выпуск поднимает версию в `package.json`.** Смена версии меняет имя
кэша: новый воркер ставится, наполняет кэш заново и сносит старый. Обновление
доезжает не мгновенно — уже открытая страница продолжает крутить старый код,
поэтому установленное на домашний экран приложение показывает новую версию со
второго запуска, а в браузере хватает перезагрузки.

Список модулей в `SHELL` собирается автоматически именно из-за этого: старый
кэш при обновлении удаляется целиком, и всё, чего нет в `SHELL`, до следующего
запуска живёт только в сети. Уйти в офлайн в этом промежутке означало бы белый
экран — `import` упёрся бы в `Response.error()`.
